# رحلات المتصفح (E2E) — ستايلو

ستة ملفات تغطي **الرحلات الأربع** وما بعد التسليم في متصفح حقيقي (Chromium)، على خادم يعمل بالبيانات التجريبية. تعمل بالترتيب، وكل رحلة تكمل الطلب الذي بدأته الرحلة السابقة:

| الملف | الرحلة | ما يُختبر |
|---|---|---|
| `1-customer` | **الزبون** (شاشة جوال) | زبون جديد يتصفح كزائر، ويضيف قطعة للسلة. عند «إتمام الطلب» يدخل برقمه والرمز، ويكتب اسمه، ويضيف عنواناً في طرابلس، ثم يطلب. يظهر الطلب في «طلباتي» بحالة «قيد الانتظار» |
| `2-store` | **المتجر** («أزياء لورا») | لوحة المتجر مفتوحة، ويصل طلب جديد فيظهر التنبيه والعدد في عنوان التبويب. يؤكد المتجر الطلب ثم يبدأ التجهيز. لا يملك زر «تسليم للسائق»، وصفحة الموظفين تعرض «ليست لديك صلاحية» |
| `3-staff-dispatch` | **إدارة ستايلو** (1) | مدير العمليات يرى تنبيه «طلبات مؤكدة بلا سائق»، ويسند الطلب لسائق متاح |
| `4-driver` | **المندوب** (شاشة جوال) | يدخل برقمه فيصل إلى «لوحة المندوب». يضغط «استلمت الطلب من المتجر» ويؤكد، ثم «تم التسليم واستلام X د.ل» ويؤكد المبلغ |
| `5-staff-custody` | **إدارة ستايلو** (2) | الطلب أصبح «تم التسليم». يقفل مدير العمليات عُهدة المندوب، فتعود إلى صفر |
| `6-returns-block-bank` | **ما بعد التسليم** | يسجّل الموظف إرجاع قطعة، فتعود للمخزون وتظهر للزبون «استرداد». يحظر الزبون، فيُرفض طلبه الجديد، ثم يلغي الحظر. يُدخل المتجر حسابه البنكي، ويُرفض رقم آيبان خاطئ، ثم يوثّقه المدير العام. معاينة تسوية المتجر تخصم المرتجع |

## التشغيل محلياً

```bash
npm run e2e:install            # مرة واحدة: الحزم + متصفح Chromium
npm run db:reset               # بيانات تجريبية نظيفة (اختياري لكن أدق)
```
شغّل الخادم برفع حد رموز الدخول، لأن الاختبارات تسجّل الدخول عدة مرات من نفس الجهاز:
- PowerShell: `$env:OTP_MAX_PER_IP_HOUR=1000; npm start`
- Linux/macOS: `OTP_MAX_PER_IP_HOUR=1000 npm start`

ثم في نافذة ثانية:
```bash
npm run e2e
```

**متغيرات اختيارية:**
- `E2E_BASE_URL`: خادم آخر، مثل `http://10.19.26.252:4000`.
- `E2E_DATABASE_URL`: قاعدة البيانات نفسها. تُستخدم لمسح رموز الدخول المعلّقة قبل التشغيل، فلا يُرفض التشغيل المتكرر بسبب «30 ثانية بين الرموز». إن لم تكن متاحة تظهر رسالة تحذير فقط.

**جهاز أو شبكة بطيئة:** لتجربة الرحلات كأن الجهاز بطيء، يؤخّر هذا الأمر كل طلب API بمقدار 800 ملّي ثانية:
```bash
E2E_SLOW_MS=800 npm run e2e
```
في PowerShell:
```
$env:E2E_SLOW_MS=800; npm run e2e
```
كل خطوة تحفظ شيئاً تنتظر رد الخادم قبل الانتقال (`untilSaved`)، والحالة تُقرأ من الـ API لا من نص الصفحة. وكل رحلة تتحقق أولاً من أن الطلب في الحالة التي تركته فيها الرحلة السابقة، وإلا ظهرت رسالة تحدد أين توقّف.

**ملاحظة:** الاختبارات تعمل على خادم **تطوير** فقط، لأنها تقرأ رمز الدخول المعروض على الشاشة. وهي تضيف طلبات حقيقية إلى قاعدة التطوير.

عند أي فشل تجد لقطة الشاشة ومسار التنفيذ في `e2e/test-results/`. افتح المسار بـ:
```bash
npx playwright show-trace <الملف>
```
في GitHub تُرفع هذه الملفات تلقائياً باسم `e2e-report`.
